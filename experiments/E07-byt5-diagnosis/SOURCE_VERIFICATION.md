# E07 sources (checked 2026-10-27) and how they informed decisions

Published findings are kept separate from this experiment's own observations. No source shows that a short LoRA
adaptation of ByT5-small should succeed on this Khmer dataset.

| Source | Checked | Published content used | Decision it informed |
|---|---|---|---|
| Hugging Face model card, `google/byt5-small` (revision `68377bdc…`) | huggingface.co/google/byt5-small | "only pre-trained on mC4 excluding any supervised training … has to be fine-tuned before it is useable on a downstream task"; works on raw UTF-8 bytes (ids = bytes + 3), no tokenizer needed | The zero-shot output is not an assessment. The audit checks byte ids against the local `config.json` (pad 0, eos 1, decoder start 0, vocab 384) rather than assuming them |
| Xue et al., "ByT5: Towards a Token-Free Future with Pre-trained Byte-to-Byte Models", TACL 2022 | aclanthology.org/2022.tacl-1.17 (abstract) | Byte-level T5 with minimal changes; byte models do better on tasks "sensitive to spelling and pronunciation" | The motivation for testing ByT5 at all. The abstract page gives no fine-tuning recipe, so none is taken from it |
| Kirov, Johny, Katanova, Gutkin, Roark, "Context-aware Transliteration of Romanized South Asian Languages", CL 50(2) 2024 | aclanthology.org/2024.cl-2.2 (abstract; the full text was read in E06, see its SOURCE_VERIFICATION.md) | Fine-tuned ByT5 (the *base* size, full fine-tuning, 50,000 steps) for single-word transliteration; fine-tuning was "quite sensitive to outliers/noise" | A one-run, mined-data adaptation is reported as conditional evidence only. E06's 1,000-update LoRA run is far smaller than the published recipe, so its failure says little about ByT5 in general. The E03 data are mined and unreviewed, so some noise is expected (e.g. *bracket* → ប្រកួត, "competition", in the tiny sample) |
| Transformers v5.19.0, T5 documentation | huggingface.co/docs/transformers/v5.19.0/en/model_doc/t5; installed `modeling_t5.py` | "T5 models need a slightly higher learning rate … `1e-4` and `3e-4` work well" (full fine-tuning); labels with −100 are ignored; `decoder_input_ids` are built from `labels` by `_shift_right`. In the installed code, −100 → pad and the start id is `config.decoder_start_token_id`; the loss is `CrossEntropyLoss(ignore_index=-100)`, a mean over non-ignored positions; the decoder output is rescaled only when `config.scale_decoder_outputs` | Audit checks 3–5 compare against the installed code, not an assumed shift. Under v5 the ByT5 config gives `scale_decoder_outputs = False` and an untied `lm_head`, which was checked because v5 sets `tie_word_embeddings = True` on the config object |
| PEFT LoRA reference | huggingface.co/docs/peft/main/en/package_reference/lora | Scaling `lora_alpha / r` (`use_rslora` False); A Kaiming-uniform, B zeros, so the adapter starts as a no-op; `target_modules="all-linear"` "can provide performance equal to a fully finetuned model"; "it may be worth targeting other layers" beyond attention | The repository's `LoRALinear` matches these defaults. Audit check 8 confirms that the zero-initialised adapter gives the base logits exactly. The tiny diagnostic and the full recipe add FFN targets (wi_0, wi_1, wo). PEFT itself was not installed, to avoid a new dependency |
