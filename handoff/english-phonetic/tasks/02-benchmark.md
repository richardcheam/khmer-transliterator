# Task 2 — Qualify the measurement, then freeze a new benchmark

**Outputs:** benchmark/data card, reference ledger, overlap report, metric controls, development/final manifests, power analysis, qualification status and frozen protocol.

## Preserve historical meaning

- [ ] Leave v1 byte-identical. Its English picks are mostly preferences chosen from E's candidates; dev-41 was used for development; romanised Khmer and Cambodian-name panels do not establish English phonetic transcription quality. Label v1 a historical diagnostic suite in the new report. Do not retroactively invalidate E01's registered outcome or promote its near miss to a pass.
- [ ] Distinguish the training-validation set (checkpoint/candidate selection), the repeatedly used historical diagnostics, and a genuinely untouched final set. A new random split of already adaptively inspected items is not automatically independent evidence.

## Reference format and eligibility

- [ ] Use one `ReferenceItem` per normalized English lexical item/intended pronunciation/accent identity; preserve all accepted spellings, evidence and source IDs. IDs are unique by that compound identity, not spelling alone: two readings of `record` may be distinct items but remain in the same lexical split/resampling group. A preferred form and the set of acceptable forms are different fields. Use NFC for Khmer canonical Unicode normalization in both references and predictions; preserve sound-bearing marks. Do not remove diacritics to inflate exact match. English normalization and grouping are declared separately.
- [ ] Quality tiers: `independent_reviewed` (documented independent human acceptance under this policy), `attested` (reliable external spelling/pronunciation evidence, without claiming exhaustive acceptance), `proxy` (automated/teacher-generated or insufficiently checked). A paper/dictionary can be independent evidence only where it actually addresses this mapping, not merely because it contains the English translation and a Khmer word.
- [ ] Qualification is per item: every qualified-primary item must have documented acceptance under this phonetic policy by a competent human reviewer independent of the new models and candidate generation, or an existing independently reviewed resource explicitly establishing this phonetic mapping. Record reviewer/resource identity, review policy, date/version, intended English reading, accepted alternatives and unresolved judgments. A translation dictionary association, provenance alone, owner preference picked from E's candidates, unreviewed web attestation, automated distance or LLM agreement does not meet this requirement. Put unadjudicated `attested` and `proxy` items in separate exploratory tracks. If no such independent evidence is available, the qualified set is empty and the final quality status is inconclusive; do not self-certify it with an unspecified audit.
- [ ] Select reference audit samples before seeing any new model's outputs, using a fixed seed and stratification by source and word class. Review evidence against the policy. If independent linguistic adjudication is unavailable, explicitly mark the affected audit as unverified; do not assign it an invented pass rate. Use already documented independent reviews where available. Do not demand a new owner annotation campaign.
- [ ] If Gemini is not already freely available and authorized through existing tools, do not call it. There are no paid requests in this project. An optional available teacher may propose candidates/checks on development only, with all outputs marked `proxy`; it cannot create and certify the final gold labels. New teacher-generated training data is outside these arms.

## Separation and coverage

- [ ] Normalize input variants and group inflections/closely related named entities before splitting. Use deterministic explicit group rules; inspect collisions and report over-grouping. All variants of one item/pronunciation group stay together. Do not apply aggressive English stemming to every foreign name.
- [ ] Check final inputs and their groups against every supervised source, model-derived draft, adaptation corpus and validation set. Audit P2G target/phone overlap separately. English pronunciation dictionary entries are intentionally usable inference resources: disclose dictionary hits, do not confuse access to English pronunciation with leakage of the English→Khmer answer.
- [ ] Freeze strata: common versus unfamiliar words; names intended as English; short/long inputs; difficult sound/cluster patterns; dictionary hits/misses; pronunciation ambiguity; target-seen versus target-unseen in P2G/monolingual resources. Group sampling/resampling by lexical family so correlated variants do not count as independent evidence.
- [ ] Primary evaluation is end-to-end from the English word using the deployed frozen default dictionary/G2P pipeline, without supplying reference phones to the model. Fix the intended reading/accent independently and ensure references cover the registered default disambiguation policy before predictions. If ambiguous-item reference coverage is unavailable, flag that item before model inference and keep it in a separate diagnostic track. Do not exclude a word because the provider actually predicts the wrong phones: that is an end-to-end error. A separate supplied-pronunciation track may feed the same documented intended phones to both phone arms, but is labeled conditional/oracle-assisted and never substituted for the primary result. The letters arm receives no oracle reading information.
- [ ] Keep final model predictions unread until the architecture, checkpoints and selected candidate are fixed. Reference qualification happens before those predictions. A label correction after inspecting predictions requires a new benchmark version and disclosure; never alter references selectively to favor a model.

## Metrics and measurement checks

- [ ] Primary metric: raw beam-4 top-1, multi-reference exact match on the qualified English phonetic set, macro over independent lexical groups with the exact aggregation specified before training. Report ordinary item accuracy alongside it. If only unqualified preference references exist, call the metric `reference_agreement`, not verified phonetic correctness.
- [ ] Secondary: top-k reference coverage, minimum character error to accepted forms, and fixed-reranker results reported separately. No Latin→Khmer answer lookup in the primary neural evaluation. Freeze any reranker and its data for all arms.
- [ ] Automated phonetic diagnostics compare Khmer G2P output with intended source pronunciation using a stated adaptation-aware proxy. Raw phone equality is not a correctness definition across English/Khmer. Do not enforce a hard English-to-Khmer distance threshold without validated adaptation rules; report unvalidated diagnostics descriptively.
- [ ] Measurement controls: every known accepted alternative must pass exact scoring; a canonical-Unicode equivalent must pass; a confirmed wrong spelling/pronunciation must not pass; duplicate compound identities, duplicate/unknown IDs and prediction/reference alignment errors must be rejected. A dictionary mapping's insertion order is irrelevant: align by ID and validate coverage. Missing predictions count as failures and are reported, not silently dropped; unknown extra prediction IDs are errors. Nonempty/unique IDs and references are mandatory. Multiple pronunciations of one spelling are legal distinct items within the same lexical group.
- [ ] Validate that the chosen primary metric discriminates independently accepted alternatives from confirmed errors on a documented control sample. Surface false rejections/acceptances and uncertain cases; a pipeline's unit-test pass does not certify reference quality.

## Power, uncertainty and decisions

- [ ] Practical threshold `delta = 5.0` percentage points. Before full jobs, use development-only paired discordance estimates or a declared sensitivity grid to simulate test-set sizes needed for 80% power at two-sided 5% significance. Record assumptions, dependence/grouping and attainable sample sizes. Do not derive a claimed powered design from an already inspected final treatment effect. P7 explains power analysis; use it as guidance, not an obligation to add a toolkit dependency.
- [ ] Freeze the attainable final set even if the target sample size cannot be obtained; mark inadequate sensitivity and expect `inconclusive`. Do not fabricate hundreds of references to reach a number. More training seeds cannot replace word coverage or independent labels.
- [ ] Final comparison uses the same lexical groups across paired arms and all three seeds. Use 10,000 paired group bootstrap resamples with a fixed bootstrap seed, averaging each group's paired differences over seeds. Report the 95% interval as conditional on these trained seeds; separately show every seed, mean and spread. With three seeds do not claim full training-population uncertainty is solved. Compute decisions from unrounded counts/weights.
- [ ] Evidence fields are separate: `positive_effect_supported` requires interval lower bound > 0; `meaningful_gain_ruled_out_conditional` requires interval upper bound < 5; `practically_equivalent_conditional` requires the entire interval strictly within [-5,+5]. These can overlap (a positive small effect). If the interval spans zero and useful gains, it is inconclusive. Apply the reference qualification and seed caveats to every label.
- [ ] Adoption is a separate conservative rule: qualified benchmark; mean primary gain >= 5; positive gain in at least 2/3 seeds; conditional interval lower bound > 0; no demonstrated violation of phonetic/orthographic controls; product latency/memory within Task 5 limits. A failed adoption rule means do not promote, not proof of zero improvement.
- [ ] For the summary status: `supported_improvement` for qualified positive evidence (report whether adoption passed); `meaningful_gain_not_supported` only when qualified data conditionally rule out +5 (explain this does not prove zero); otherwise `inconclusive`. Always include the component fields, not only a coarse label.
- [ ] Commit benchmark/protocol/config and their hashes before full training. No routine user confirmation is required. Qualified or not, advance to Task 3 with the correct scientific status.
