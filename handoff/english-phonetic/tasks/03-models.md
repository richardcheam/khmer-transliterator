# Task 3 — Comparable models and pronunciation transfer

**Inputs:** audited eligible data, frozen protocol/config, current compact model.
**Outputs:** tested source pipeline, three arm implementations, P2G trainer, deterministic exports and smoke evidence.

## Shared implementation

- [ ] Start with the current compact architecture: d=192, encoder/decoder layers=3/3, heads=4, FF=512, GELU, dropout=0.1. Inspect actual configuration and preserve necessary implementation-specific settings. Avoid expanding model capacity in only one arm.
- [ ] Build a common source vocabulary containing the training letters, task markers and registered English/Khmer phone inventories for all three arms, and a common Khmer output vocabulary from eligible supervised/P2G training material. No vocabulary built from final reference answers. Common vocabulary/order makes matching tensors and initial parameter counts comparable, even when letters arm does not use phone tokens. Clearly distinguish phone symbols from Unicode characters; a multi-character phone must not be split accidentally.
- [ ] Set maximum source/target lengths from eligible training/development data and the frozen resource inventories before full training. Prefer variable-length padding and sufficient registered positional capacity over truncation. Explicitly reject oversized runtime input with a documented status. No silent cutting of English letters, phones, Khmer marks or EOS.
- [ ] Use named deterministic initialization streams and private data-order generators. For a paired seed, copy matching initial tensors by name/shape across arms and use identical supervised batch IDs. Matching initial random seeds alone is not proof of matching tensors. Do not require identical dropout masks or identical losses after the arms receive different inputs or pretraining.

## English phones as input

- [ ] Reuse `en_g2p.py` where correct. Define one pronunciation alphabet/version, accent and stress policy. CMUdict alternative readings are retained in provenance; choose a deterministic first-listed default and flag ambiguity unless supplied pronunciation selects a reading. Use the same handling at training and deployment, not oracle dictionary readings at evaluation only.
- [ ] Implement `get_pronunciation` and `encode_source` from the plan. `letters` receives letters plus task marker; `phones`/`phones_p2g` receive those same letters plus a separator and phone tokens. Preserve English spelling alongside phones.
- [ ] Dictionary miss handling: use the registered local G2P provider if available and eligible. If unavailable, mark `<NO_PRON>` explicitly. Both phone-input arms must see this token on actual training misses; add a fixed 10% source-phone dropout on supervised training examples in both arms so missing pronunciation is supported at runtime. Register the dropout and its private RNG before full training. It is never applied to supplied evaluation pronunciations.
- [ ] Separate `provided`, `dictionary`, `g2p`, `unavailable` pronunciation statuses. A guessed phone sequence is not a verified linguistic label. Cache by normalized word, provider/resource version, accent and supplied pronunciation, not by spelling alone.
- [ ] Keep source encoding identical in PyTorch training, greedy validation, NumPy beam inference and CLI. Use held-out development fixtures to prove byte/token equality. Public APIs accept explicit phones in the registered alphabet and reject unrecognized tokens clearly.

## Khmer P2G pretraining

- [ ] Use Khmer-script headword→pronunciation entries from eligible resources, reverse the pairs to phones→Khmer spelling and add a `KM_P2G` task marker. Do not use Latin word→Khmer answer entries disguised as monolingual pretraining. Keep alternative spellings for homophonous inputs; do not arbitrarily delete them as duplicates.
- [ ] Split P2G training/development by connected spelling/pronunciation groups so the validation result does not simply recognize an alternate form of the same entry. Apply the registered final target-unseen exclusions, and disclose overlap on the target-seen track. Preserve final English-pair exclusions.
- [ ] Initialize the same shared model and train a maximum of 10 epochs/2 elapsed hours per seed, selecting only on P2G development loss. Do not assume native-word inverse-lexicon accuracy proves loanword quality. Keep best checkpoint and actual elapsed time. For treatment confirmation, use independent P2G jobs for seeds 1 and 2 rather than silently sharing one lucky pretrained checkpoint across every seed.
- [ ] Transfer encoder/decoder/embedding parameters using the common vocabulary. Fine-tune on exactly the same supervised batches as the other arms. To limit forgetting, insert one eligible P2G replay batch after every 8 supervised updates in `phones_p2g`, using a fixed separate RNG and full ordinary cross-entropy for that replay batch. No replay in the other arms. Register this as part of the C recipe: C tests pretraining plus replay as one transfer recipe, not pretraining in isolation. Count replay compute and steps separately.
- [ ] Keep E01's auxiliary decoder out of all three arms to avoid mixing a second method comparison into this experiment. Do not claim E01 showed phone inputs fail/succeed: reconcile its actual source path first.
- [ ] If no eligible P2G dataset exists, mark C unavailable before full training. Do not replace it with a new objective or a large checkpoint.

## Supervised training defaults and checks

- [ ] Reuse the working repository optimizer/schedule: CPU FP32, AdamW lr=1e-3, weight_decay=0.01, 500 supervised warm-up steps followed by cosine, label smoothing=0.1, batch=128, gradient clipping=1.0, 40 epochs, at most 6 threads. Compute schedule length from actual supervised steps. The P2G replay must not advance the supervised learning-rate schedule; give pretraining its own schedule and record replay LR policy. If local code uses a materially different baseline recipe, resolve and freeze one shared recipe before training.
- [ ] Select checkpoints on the new English validation primary metric, full precision; tie-break by lower validation loss, then earlier epoch. Fixed beam-4 validation is preferred if affordable; if greedy validation is used, register it for all arms and disclose the difference from final beam scoring. Never use v1/final panels for selection.
- [ ] Test: known dictionary input; miss with G2P; miss without G2P; ambiguous reading/default and supplied pronunciation; unknown phone; Unicode input; empty input; too-long input; P2G homophones; exact matching initialization tensors; correct paired batch IDs; no final-reference reads by training; checkpoint epoch matches selected epoch.
- [ ] Smoke: one tiny supervised overfit test on artificial/dev-only pairs proves learning and export; one P2G mini-job proves transfer/replay; verify finite losses and gradients. A small overfit test proves implementation, not generalization.
- [ ] Export intermediate/final models and verify source tokens, greedy tokens, top-k spellings and numerical logits against PyTorch on fixed development fixtures. Preserve existing tolerance of approximately 1e-6 where available; disclose any measured platform-specific numerical tolerance. No forced equality by changing outputs after inference.
- [ ] Commit tested code and locked config. Continue automatically to the experiment queue.
